# 티스토리 글 가져오기

예전 티스토리 글은 대제목·소제목 없이 문단만 길게 이어지고 이미지가 많다. 그 글을
이 블로그로 옮기면서 **문장은 한 글자도 바꾸지 않고 구조만 얹는 것**이 이 스킬의 일이다.

문장을 바꾸지 않는 것이 왜 중요한가 — 옮기는 작업은 글을 고치는 작업이 아니다. 읽기
좋게 다듬고 싶은 유혹이 들지만, 그건 글쓴이가 나중에 직접 판단할 일이다. 옮기는 단계에서
문장이 슬쩍 바뀌면 어디가 원문이고 어디가 손댄 곳인지 아무도 모르게 된다. 그래서 이
스킬은 변환을 기계에 맡기고, 결과가 원문과 같은지도 기계로 확인한다.

## 작업 순서

### 1. slug를 정한다

파일명과 이미지 폴더명이 되고 URL에도 들어간다. 영문 소문자와 하이픈만 쓴다.
글 주제를 짧게 담되 원문 제목을 그대로 음차하지 않는다 — 한글 제목은 URL에서 길어진다.

```
"위임의 시대, 근데 나도 모르게 위임한 것들"  →  delegation-cache-headers
```

### 2. 가져온다

이미지 변환에 `cwebp`·`gif2webp`가 필요하다. 없으면 원본 포맷 그대로 저장되고
경고가 뜬다 — 작업이 멈추지는 않지만 레포에 원본 용량이 그대로 남는다.

```bash
command -v cwebp || brew install webp
python3 .claude/skills/import-tistory/scripts/fetch_post.py "<URL>" --slug <slug>
```

만들어지는 것:

| 파일 | 성격 |
| --- | --- |
| `.import-tistory/<slug>.raw.md` | 기계 변환된 본문. **편집하지 않는다.** 비교 기준 |
| `.import-tistory/<slug>.meta.json` | 제목·작성일·태그·이미지 목록 |
| `src/content/posts/<slug>/image-N.webp` | 내려받아 WebP로 변환한 이미지 |

**작업 파일이 `src/content/posts/` 밖에 있는 것은 의도된 것이다.** 컬렉션 로더가
`**/*.md`를 훑기 때문에 `.raw.md`를 posts 안에 두면 그것도 글로 인식되고, frontmatter가
없어 빌드가 스키마 오류로 실패한다. dev 서버가 떠 있으면 곧바로 에러 화면이 뜬다.
`.import-tistory/`는 `.gitignore`에 등록되어 있다.

출력에 `이미지 : 8/8개 저장 (1024KB → 210KB WebP)` 처럼 저장 결과가 나온다.
**분모와 분자가 다르면 즉시 다시 실행한다.**
티스토리 CDN 주소에는 `expires`·`signature`가 붙어 며칠 뒤 만료된다. 지금 실패한 이미지는
나중에 같은 주소로 다시 받을 수 없고, 글 페이지를 새로 읽어 새 주소를 받아야 한다.

### 3. 구조를 얹는다

`.import-tistory/<slug>.raw.md`를 읽고, 그것을 바탕으로 `src/content/posts/<slug>.md`를
만든다. 원본은 그대로 남긴다.

**할 수 있는 것은 두 가지뿐이다.**

1. frontmatter를 앞에 붙인다
2. 문단 사이에 `##`·`###` 제목 줄을 끼운다

문단의 순서를 바꾸거나, 문장을 합치거나 쪼개거나, 표현을 다듬거나, 요약을 덧붙이는 것은
하지 않는다. 이미지 위치도 원문 그대로 둔다.

**제목 문구는 원문에서 딴다.** 글에 이미 있는 표현을 짧게 잘라 쓰는 것이 가장 안전하고,
글쓴이의 말투가 유지된다. 예전 글에는 "첫 번째는 ~입니다", "정답은 ~입니다" 같은 문장이
자주 나오는데 그런 대목이 구간의 시작점이다.

```
원문 문단: "나도 모르게 위임한 것 첫 번째는 캐시 헤더입니다. 인터렉션 가능한 화면을…"
넣을 제목: ## 위임한 것 첫 번째, 캐시 헤더
```

제목을 넣었다고 그 문장을 본문에서 지우면 안 된다. 제목은 **추가**이고 본문은 그대로 남는다.

**개수는 3~7개 정도.** 목차는 항목이 둘 이상일 때만 나타나고(`TableOfContents.astro`),
너무 촘촘하면 목차가 본문만큼 길어진다. 화제가 바뀌는 지점만 잡는다. `###`는 `##` 안에서
사례가 여러 개로 갈릴 때만 쓴다.

### 4. frontmatter를 채운다

```yaml
---
title: '<meta.json의 title>'
description: '목록 카드와 검색 결과에 쓰일 한 줄'
pubDate: <meta.json의 published 중 날짜 부분>
tags: ['<주제>', '<주제>']
cover: ./<slug>/image-1.webp
---
```

`description`은 원문에 없는 항목이라 새로 써야 한다. 본문 첫 문단의 취지를 벗어나지 않게
한 문장으로 쓴다. 본문을 요약해 넣는 것이지 본문에 문장을 추가하는 것이 아니므로 괜찮다.

`pubDate`는 원문 작성일을 쓴다. 새로 쓴 날짜를 넣으면 옮긴 글이 목록 맨 위로 올라가
시간 순서가 뒤집힌다. `meta.json`의 `published`가 `2026-08-12T13:51:24+09:00` 형태이면
`2026-08-12`만 쓴다.

`cover`는 첫 이미지를 쓰는 것이 자연스럽다. 목록에서 대표 이미지로 보인다. 첫 이미지가
글을 대표하지 못하면(예: 오류 스크린샷) 더 적절한 것을 고른다. 이미지가 없으면 생략한다.

### 5. 검증한다 — 건너뛰지 않는다

```bash
python3 .claude/skills/import-tistory/scripts/verify.py \
  .import-tistory/<slug>.raw.md src/content/posts/<slug>.md
```

`통과`가 나와야 끝난 것이다. 문단이 수십 개인 글에서 문장이 미묘하게 바뀌었는지 눈으로
확인하는 것은 불가능하다. 이 스크립트가 heading과 frontmatter를 제외한 나머지를 문장
단위로 비교해 사라진 문장과 새로 생긴 문장을 짚어준다.

`실패`가 나오면 표시된 차이를 원문대로 되돌린다. **차이를 남긴 채 넘어가지 않는다.**
정말 원문이 틀렸다고 판단되면(오타 등) 사용자에게 알리고 판단을 받는다.

### 6. 정리하고 빌드한다

검증을 통과했으면 작업 파일을 지운다. `.gitignore`에 걸려 있으니 남겨둬도 커밋되지는
않지만, 다음 글을 옮길 때 헷갈리지 않도록 정리한다.

```bash
rm .import-tistory/<slug>.raw.md .import-tistory/<slug>.meta.json
nvm use && npm run build
```

빌드가 통과하면 스키마 검증도 통과한 것이다. `npm run dev`로 글을 열어 이미지가 모두
보이는지, 목차가 제대로 잡혔는지 확인하고 사용자에게 보고한다.

## 알아두면 좋은 것들

**본문 경계** — 스크립트가 `contents_style` 컨테이너를 div 깊이를 세어 잘라낸다. 단순히
다음 `</div>`를 찾으면 본문이 일찍 끊기고, 문서 끝까지 가면 "카테고리의 다른 글" 목록과
티스토리 툴바가 본문에 섞여 들어온다. 변환 결과에 관련글 제목이나 표가 보이면 이 경계가
어긋난 것이므로 `slice_body()`의 선택자를 확인한다.

**코드블록 언어** — 티스토리는 `data-ke-language="typescript"` 속성에 언어를 담아둔다.
스크립트가 이를 읽어 ` ```typescript ` 로 내보내므로 Shiki 하이라이팅이 그대로 붙는다.

**줄나눔** — 원문의 `<br>`은 두 칸 + 개행(마크다운 hard break)으로 옮긴다. 단일 개행으로
두면 마크다운이 공백으로 합쳐 원문의 줄나눔이 사라진다.

**이미지가 많은 글** — 예전 글은 이미지를 적극적으로 쓴 경우가 많다. 이미지는 본문에서
설명을 뒷받침하는 자리에 있으므로 위치를 옮기지 않는다.

용량은 **받는 시점에** 처리한다. 빌드 때 Astro가 WebP를 만들어주지만 그건 `dist` 얘기이고,
git에 영구히 남는 것은 `src`에 저장한 원본이다. 이미지는 이미 압축된 바이너리라 git의
delta 압축이 먹히지 않아 커밋된 크기가 히스토리에 그대로 쌓인다. 그래서 스크립트가 내려받은
직후 WebP로 바꿔 저장한다. 나중에 일괄 변환하면 옛 파일이 히스토리에 남아 레포가 오히려
커지므로, 이 시점이 유일한 기회다.

변환 방식은 이미지마다 다르다. 무손실과 손실(q85)을 둘 다 만들어 작은 쪽을 고르되, 손실이
무손실의 60% 이하일 때만 손실을 택한다. 평평한 UI 스크린샷은 무손실이 더 작으면서 글자도
안 뭉개지고, 지도·사진은 손실이 4~9배 작다. 애니메이션 GIF는 `gif2webp`가 프레임을 보존한다.

**여러 글을 옮길 때** — 한 번에 하나씩 끝낸다. slug 지정, 구조화, 검증이 글마다 달라서
묶어 처리하면 검증을 건너뛰기 쉽다. 사용자가 URL을 여러 개 주면 순서대로 하나씩 처리하고
각 글마다 검증 결과를 보고한다.

**다른 블로그 플랫폼** — `slice_body()`가 티스토리 스킨의 선택자 세 개를 순서대로 시도한다.
다른 플랫폼이면 본문 컨테이너를 찾지 못하고 멈춘다. 그때는 해당 사이트의 HTML을 확인해
선택자를 추가하면 나머지 흐름은 그대로 쓸 수 있다.
